AI가 '스스로 일하기' 시작하면서 vivo 블루리버 OS가 AgentOS로 진화한다

2026-09-18

서론

2022년 생성형 AI의 물결이 시작된 이래, 사람들은 AI의 강력한 "대화 및 질의응답" 능력에 처음으로 주목했습니다.

하지만 올해 들어 Agent의 빠른 발전과 함께 업계의 초점은 실질적으로 변화하고 있습니다. AI는 더 이상 조언만 제공하는 것이 아니라, 사용자 대신 직접 일을 처리합니다.

이는 AI가 더 이상 단순한 질의응답 문제에 직면하는 것이 아님을 의미합니다. AI는 시나리오를 인지하고, 복잡한 목표를 분해하며, 도구를 자율적으로 호출하고, 예외 상황 발생 시 처리 방법과 결과 검증 방법을 알아야 합니다.

이러한 이유로 업계의 기술적 중심은 "Harness 엔지니어링"으로 발전하기 시작했습니다.

간단히 말해, 대규모 언어 모델을 사고를 담당하는 "두뇌"에 비유한다면, Harness는 이 두뇌가 실제로 작동하도록 하는 "작업 기반"이며, AI가 "답변할 수 있는" 수준에서 "실행하고, 지속하며, 검증할 수 있는" 수준으로 도약하게 합니다.

그러나 AI가 실제로 애플리케이션 간 작업을 실행하기 시작하면, 필연적으로 하위 권한 관리, 데이터 액세스 및 장치 스케줄링에 접하게 됩니다. 이는 분명히 단일 앱이 제어할 수 있는 범위를 넘어섭니다.

따라서 운영체제는 Agent 시대의 새로운 인프라가 되는 것이 당연합니다.

이러한 기술 발전에 발맞춰 vivo는 자체 개발한 BlueOS를 기반으로 AGI 시대를 위한 AgentOS 탐색을 공식적으로 시작했습니다.

핵심은 Agent Harness(Agent 실행 기반)를 운영체제에 깊이 통합하여 시스템 코어에 전용 Agent 프레임워크를 구축하고, 시스템이 의도 이해, 작업 계획, 도구 스케줄링 등의 기능을 기본적으로 갖추도록 하는 것입니다.

이는 BlueOS가 탄생 초기부터 가졌던 포지셔닝, 즉 vivo가 AGI 시대를 위해 자체 개발한 지능형 운영체제와도 일맥상통합니다.

BlueOS 4-AgentOS 기술 프리뷰 발표

9월 16일, 2026 vivo 개발자 컨퍼런스가 선전에서 개최되었습니다.

vivo는 BlueOS 4-AgentOS 기술 프리뷰(이하 BlueOS AgentOS)를 공식 발표했습니다. 이는 Agent 시대를 위한 시스템 수준의 탐색으로, 핵심은 한 문장으로 요약할 수 있습니다. "인간-기계 상호작용, 시스템 아키텍처, 애플리케이션 생태계를 지속적으로 심화하고, '작업 중심'에 초점을 맞춰 사용자를 이해하고, 장치를 이해하며, 작업을 수행할 수 있는 지능형 경험을 구축합니다."

인간-기계 상호작용의 변화

기존 휴대폰 사용 논리는 매우 고정적입니다. 배달을 주문하려면 배달 앱을 열고, 항공권을 조회하려면 여행 앱을 열고, PPT를 만들려면 오피스 소프트웨어를 열고, 데이터를 처리하려면 스프레드시트 도구를 찾아야 합니다.

사용자는 "어떤 일에 어떤 앱을 사용해야 하는지" 스스로 기억하고, 다른 애플리케이션 간에 전환해야 합니다.

AgentOS는 이러한 복잡한 작업을 시스템에 맡깁니다. 사용자는 "어떤 앱을 열어야 할까"를 먼저 생각할 필요 없이, 자신이 무엇을 하고 싶은지 직접 말합니다. 예를 들어, "오늘 회의 내용을 보고서 PPT로 정리해 줘."라고 말하면, 시스템은 이 목표를 이해한 후 회의 기록을 찾아보고, 관련 프로젝트 자료를 읽고, 해당 도구를 호출하여 내용을 정리한 다음 최종 결과를 사용자에게 전달할 수 있습니다.

이것이 BlueOS AgentOS가 인간-기계 상호작용에서 추구하는 중요한 방향입니다. 즉, "기능 조작"에서 "의도 표현"으로 점진적으로 전환하는 것입니다.

물론 시스템이 능동적으로 작업을 완료한다고 해서 사용자가 아무것도 신경 쓸 필요가 없다는 의미는 아닙니다.

오히려 BlueOS AgentOS의 설계에서는 "능동적 실행"과 "사용자 제어 가능성"이 완벽하게 공존합니다. vivo는 이를 위해 "세 화면 연동" 상호작용 경험을 제공합니다. 이 중 대화 센터는 사용자가 의도를 표현하고 최종 결과를 받는 주요 입구입니다.

  • 사용자는 음성, 텍스트, 이미지, 파일 등 자연스러운 방식으로 시스템에 자신이 무엇을 하고 싶은지 직접 전달할 수 있습니다.
  • 예를 들어, 사용자가 "다음 주 베이징 출장 전체 일정을 계획해 줘."라고 말하면, 시스템은 실제로 실행을 시작하기 전에 작업에 필요한 권한(예: 일정 읽기, 웹 검색, 출장 앱 액세스 등)을 먼저 정리하고, 사용자에게 일괄적으로 승인을 요청합니다.
  • 사용자가 확인하면 Agent는 백그라운드에서 자율적으로 진행하여 가격 비교, 일정 확인, 계획 수립 등을 수행하며, 사용자는 현재 페이지에 머물러 기다릴 필요가 없습니다. 작업이 완료되면 최종 일정표는 대화 센터로 직접 전달됩니다.
  • 이렇게 되면 사용자가 보는 것은 더 이상 여러 앱을 오가는 복잡한 작업이 아니라, "요구 사항 제시 - 권한 확인 - 결과 대기 - 완성품 수령"이라는 극도로 간소화된 과정입니다.
  • 대화 센터를 오른쪽으로 스와이프하면 작업 센터로 진입합니다. 여기에는 결정 대기 중, 진행 중, 완료된 모든 작업이 집중적으로 표시됩니다. 사용자에게는 마치 "작업 진행 상황 전체 보기"와 같아서, 시스템이 현재 무엇을 하고 있는지, 어느 단계까지 진행되었는지, 자신의 확인이 필요한지 등을 한눈에 알 수 있습니다.
  • 만약 도중에 요구 사항이 변경되면, 사용자는 언제든지 작업을 개입, 조정 또는 중단할 수 있습니다.
  • 대화 센터를 왼쪽으로 스와이프하면 애플리케이션 센터로 진입합니다. 이 부분은 Agent의 등장으로 인해 기존 아이콘을 모두 버리지 않았습니다. 전화 걸기, 사진 촬영 등 목표가 매우 명확하고 조작 경로가 매우 짧은 고빈도 기능의 경우, 아이콘을 직접 클릭하는 것이 여전히 가장 효율적이므로 기존 애플리케이션 입구가 합리적으로 유지됩니다.
  • 세 화면은 각기 다른 역할을 합니다. 대화 센터는 의도 표현을 담당하고, 작업 센터는 과정을 명확히 보여주며, 애플리케이션 센터는 기존의 고빈도 작업을 유지합니다. 소비자에게는 이것이 AgentOS의 가장 직관적인 경험 변화일 것입니다. 휴대폰은 여전히 예전처럼 사용할 수 있지만, 작업이 번거롭고 복잡해지면 과정을 시스템에 안심하고 맡길 수 있습니다.

BlueOS Harness 시스템 수준 기반

앞서 언급된 유려한 경험은 시스템에 채팅 창 하나를 추가하고 대규모 언어 모델을 연결하는 것만으로는 결코 실현될 수 없습니다. 만약 기존의 앱 형태에만 의존한다면, AI는 종종 단일 애플리케이션 내에서만 "맴돌며", 애플리케이션 간 데이터 장벽, 백그라운드 유지의 어려움, 장치 간 협업의 약점 등 수많은 시스템 수준의 병목 현상에 직면하게 됩니다.

AI가 경계를 넘어 "여러 지역 출장 총괄 계획" 또는 "장치 간 전문 도구 스케줄링"과 같이 주기가 길고 관련 노드가 많은 복잡한 작업을 자율적으로 완료하게 하려면, 운영체제는 하위 실행 논리를 재구성해야 합니다.

이를 위해 BlueOS AgentOS의 핵심 기술 돌파는 Harness(Agent 실행 기반)를 시스템과 깊이 통합하여 BlueOS Harness 시스템 수준 기반을 구축하는 데 있습니다. 이는 기존의 앱을 경계로 하는 자원 스케줄링 방식을 깨고, 작업이 처음부터 끝까지, 애플리케이션과 장치를 넘나들며 안정적으로 실행되도록 합니다.

이 시스템 수준 기반은 다섯 가지 핵심 모듈의 깊은 협력으로 간단히 이해할 수 있습니다.

  • 첫 번째는 컨텍스트 엔진입니다.

    AI의 이전 "기억"은 단순히 정보를 저장하는 것이었지만, 기억하는 것이 현재 요구 사항을 이해하는 것과 같지는 않습니다. 예를 들어, 시스템에 출장을 계획하라고 요청하면, 시스템은 사용자가 어디를 방문했는지 아는 것뿐만 아니라, 내일의 일정 회의, 선호하는 항공편 시간 및 현재 장치 상태를 정확하게 파악해야 합니다. 컨텍스트 엔진은 선호도, 기록 및 현재 환경을 종합하여 작업에 진정으로 유용한 정보를 동적으로 매칭합니다. 동시에, 필요에 따라 정보를 읽어 무관한 개인 정보의 무단 액세스를 엄격히 방지합니다.

  • 두 번째는 작업 엔진입니다.

    이는 주로 Agent가 직면하는 "실행이 쉽게 중단되고, 장기적으로 진행할 수 없는" 문제점을 해결하는 데 사용됩니다. BlueOS AgentOS는 작업의 분해, 실행 및 검증을 분리합니다. 더 중요한 것은 작업 상태의 영구 저장을 지원한다는 것입니다. 며칠에 걸친 복잡한 작업 도중에 네트워크 연결이 끊기거나 도구에 이상이 발생하더라도, 시스템은 "어느 단계까지 진행되었는지"를 정확히 기억하고, 복구 후 계속 진행하며, 기계적으로 처음부터 다시 시작하지 않습니다.

  • 세 번째는 능력 버스입니다.

    이는 "교차 영역 스케줄링"의 난제를 해결합니다. 미래의 완전한 작업은 여러 장치 협업을 필요로 할 수 있습니다. 예를 들어, 고객 방문을 준비하려면 휴대폰의 이메일, PC의 전문 문서, 그리고 시계의 실시간 알림을 연동해야 합니다. 능력 버스는 하드웨어와 소프트웨어의 고립을 완전히 깨고, 휴대폰, 시계, PC 및 클라우드에 분산된 능력을 통합적으로 연결하며, 작업 요구 사항에 따라 가장 적합한 장치를 자동으로 선택하여 실행합니다.

  • 네 번째는 실행 환경 및 샌드박스입니다.

    Agent가 진정한 "생산성"을 갖추도록, 특히 사무실 및 개발 시나리오에 대응하기 위해 BlueOS는 기존 모바일 단말의 제한을 넘어 표준화된 Linux 실행 환경을 제공하고, 다른 작업을 독립적인 샌드박스로 격리합니다. 이는 Agent가 간단한 인터페이스를 호출할 수 있을 뿐만 아니라, Python, Shell 등의 구성 요소를 안전하고 안정적으로 실행하고, 심지어 성숙한 개발자 도구 체인을 사용할 수 있음을 의미합니다.

  • 다섯 번째는 보안 거버넌스 시스템입니다.

    능력이 강해질수록 경계는 더욱 명확해야 합니다.

    AI가 "질문에 답하는" 수준에서 사용자 대신 이메일을 보내고, 민감한 파일을 읽고, 심지어 장치 간 작업을 수행할 수 있는 수준으로 진화할 때, "무엇을 할 수 있는지"와 "무엇을 해야 하는지"에 대한 명확한 보안 정책이 필요합니다. BlueOS AgentOS는 최소 필요 원칙을 강조합니다. 작업 시작 전 목표와 권한 경계를 명확히 하고, 실행 중 민감한 데이터 액세스를 엄격히 제어하며, 핵심 애플리케이션 간 작업은 전체 과정을 기록하고 추적 가능하도록 합니다.

    더 중요한 것은 사용자가 항상 최종 결정권을 보유한다는 것입니다. 간단히 말해, Agent는 사용자 대신 실행할 수 있지만, 사용자 대신 모든 것을 결정할 수는 없습니다.

BlueOS AgentOS의 응용 시나리오

시스템이 하위 능력을 통합하면 BlueOS AgentOS의 응용 시나리오는 매우 상상력이 풍부해집니다.

이번 기술 프리뷰에서는 오피스 Agent와 코딩 Agent가 주목할 만한 두 가지 방향입니다. 오피스 Agent는 언제든지 호출할 수 있는 모바일 오피스 파트너와 같습니다. 문서, 회의록, 데이터 자료 등의 내용에 대해 사용자는 직접 단계별로 정리할 필요 없이, 목표를 직접 설명하면 Agent가 작업을 분해하고, 도구를 호출하며, 결과를 전달합니다.

코딩 Agent는 더욱 직접적입니다.

기존 코딩은 종종 컴퓨터 없이는 불가능했지만, BlueOS AgentOS는 이러한 능력을 모바일 단말로 더욱 확장합니다. 개발자는 음성, 텍스트, 심지어 이미지를 통해 자신의 요구 사항을 설명할 수 있으며, Agent는 단말에서 코드를 생성하고, 컴파일 환경을 호출하며, 프로그램을 실행하고, 실제 장치에서 미리 보고 검증합니다.

  • 개발자에게는 "휴대용 작업 파트너"가 될 수 있습니다. 잠시 컴퓨터를 떠나더라도 코드 수정, 문제 해결 및 일부 On-Call 작업을 처리할 수 있습니다.
  • 일반 사용자에게는 "주머니 속 생활 파트너"로 이해할 수 있습니다. 미래에는 복잡한 개발 도구를 먼저 배울 필요 없이, 자신의 요구 사항을 명확하게 설명할 수 있다면 시스템이 간단한 앱이나 자동화 도구를 생성할 기회를 가질 수 있습니다.

물론 이러한 능력은 현재 기술 탐색 및 프리뷰 단계에 있지만, 이는 엄청난 상상력을 발휘하며 미래를 기대하게 합니다.

BlueOS의 발전 과정

시간을 길게 보면, BlueOS AgentOS는 사실 물 흐르듯 자연스럽게 축적된 결과입니다.

  • 2018년 일찍이 BlueOS는 관련 연구 개발을 시작했습니다.
  • 2023년, BlueOS가 공식 발표되었고, vivo WATCH 3에 처음 탑재되었습니다.
  • 2024년, BlueOS 2가 발표되어 풀 스택 Rust 기술 로드맵을 더욱 추진하고, 자체 개발한 Rust BlueOS 커널을 추가했습니다.
  • 2025년, BlueOS 커널이 공식적으로 오픈 소스화되었고, Open Atom Open Source Foundation의 BlueKernel 인큐베이션 프로젝트가 되어 더욱 개방적인 공동 구축 단계에 진입했습니다.

BlueOS 발표 이후, BlueOS의 기술 로드맵도 지속적으로 발전해 왔습니다. 커널, 시스템 프레임워크부터 단말 AI에 이르기까지 지난 몇 년간의 축적이 오늘날 AgentOS 탐색의 기반을 형성했습니다. 이 4년간의 기반 덕분에 BlueOS는 "경계를 넘는" 데 성공했습니다.

과거 BlueOS의 적용 범위는 주로 스마트워치와 같은 IoT 장치에 집중되었습니다. 이번 AgentOS 기술 프리뷰는 BlueOS가 더 복잡한 단말 시나리오로 확장될 가능성을 보여주었습니다. 휴대폰에서의 작업 실행, 단말 코딩, 또는 휴대폰, 시계, PC 및 클라우드 간의 능력 스케줄링 등 모두 BlueOS가 기존 시스템 능력을 더 많은 장치와 사용 시나리오로 확장하려 시도하고 있음을 보여줍니다.

총평

vivo는 하위 기술력을 과시하며 업계의 질문에 답하고자 합니다. AI가 "대화"에서 "작업 수행"으로 진화할 때, 미래의 운영체제는 어떤 모습이어야 할까요? BlueOS AgentOS의 답은 "사용자와 디지털 세계를 연결하는 '슈퍼 작업 허브'가 되는 것"입니다.

이는 인간-기계 상호작용의 논리를 재정의할 것입니다. 사용자에게는 "앱 찾기, 버튼 클릭"에서 "목표 지시, 시스템 결과 제출"로 작업 방식이 변화하고, 개발자에게는 자신의 서비스가 Agent에 의해 즉시 이해되고 호출되도록 하는 것이 AI 시대의 새로운 입구를 선점하는 핵심이 될 것입니다.

BlueOS AgentOS의 이번 등장은 AGI 시대를 향한 첨단 기술의 예고편에 가깝지만, 이 강력한 시연을 통해 vivo는 차세대 운영체제의 진화 방향을 미래에 명확하게 제시했습니다.

서론

2022년 생성형 AI의 물결이 시작된 이래, 사람들은 AI의 강력한 "대화 및 질의응답" 능력에 처음으로 주목했습니다.

하지만 올해 들어 Agent의 빠른 발전과 함께 업계의 초점은 실질적으로 변화하고 있습니다. AI는 더 이상 조언만 제공하는 것이 아니라, 사용자 대신 직접 일을 처리합니다.

이는 AI가 더 이상 단순한 질의응답 문제에 직면하는 것이 아님을 의미합니다. AI는 시나리오를 인지하고, 복잡한 목표를 분해하며, 도구를 자율적으로 호출하고, 예외 상황 발생 시 처리 방법과 결과 검증 방법을 알아야 합니다.

이러한 이유로 업계의 기술적 중심은 "Harness 엔지니어링"으로 발전하기 시작했습니다.

간단히 말해, 대규모 언어 모델을 사고를 담당하는 "두뇌"에 비유한다면, Harness는 이 두뇌가 실제로 작동하도록 하는 "작업 기반"이며, AI가 "답변할 수 있는" 수준에서 "실행하고, 지속하며, 검증할 수 있는" 수준으로 도약하게 합니다.

그러나 AI가 실제로 애플리케이션 간 작업을 실행하기 시작하면, 필연적으로 하위 권한 관리, 데이터 액세스 및 장치 스케줄링에 접하게 됩니다. 이는 분명히 단일 앱이 제어할 수 있는 범위를 넘어섭니다.

따라서 운영체제는 Agent 시대의 새로운 인프라가 되는 것이 당연합니다.

이러한 기술 발전에 발맞춰 vivo는 자체 개발한 BlueOS를 기반으로 AGI 시대를 위한 AgentOS 탐색을 공식적으로 시작했습니다.

핵심은 Agent Harness(Agent 실행 기반)를 운영체제에 깊이 통합하여 시스템 코어에 전용 Agent 프레임워크를 구축하고, 시스템이 의도 이해, 작업 계획, 도구 스케줄링 등의 기능을 기본적으로 갖추도록 하는 것입니다.

이는 BlueOS가 탄생 초기부터 가졌던 포지셔닝, 즉 vivo가 AGI 시대를 위해 자체 개발한 지능형 운영체제와도 일맥상통합니다.

BlueOS 4-AgentOS 기술 프리뷰 발표

9월 16일, 2026 vivo 개발자 컨퍼런스가 선전에서 개최되었습니다.

vivo는 BlueOS 4-AgentOS 기술 프리뷰(이하 BlueOS AgentOS)를 공식 발표했습니다. 이는 Agent 시대를 위한 시스템 수준의 탐색으로, 핵심은 한 문장으로 요약할 수 있습니다. "인간-기계 상호작용, 시스템 아키텍처, 애플리케이션 생태계를 지속적으로 심화하고, '작업 중심'에 초점을 맞춰 사용자를 이해하고, 장치를 이해하며, 작업을 수행할 수 있는 지능형 경험을 구축합니다."

인간-기계 상호작용의 변화

기존 휴대폰 사용 논리는 매우 고정적입니다. 배달을 주문하려면 배달 앱을 열고, 항공권을 조회하려면 여행 앱을 열고, PPT를 만들려면 오피스 소프트웨어를 열고, 데이터를 처리하려면 스프레드시트 도구를 찾아야 합니다.

사용자는 "어떤 일에 어떤 앱을 사용해야 하는지" 스스로 기억하고, 다른 애플리케이션 간에 전환해야 합니다.

AgentOS는 이러한 복잡한 작업을 시스템에 맡깁니다. 사용자는 "어떤 앱을 열어야 할까"를 먼저 생각할 필요 없이, 자신이 무엇을 하고 싶은지 직접 말합니다. 예를 들어, "오늘 회의 내용을 보고서 PPT로 정리해 줘."라고 말하면, 시스템은 이 목표를 이해한 후 회의 기록을 찾아보고, 관련 프로젝트 자료를 읽고, 해당 도구를 호출하여 내용을 정리한 다음 최종 결과를 사용자에게 전달할 수 있습니다.

이것이 BlueOS AgentOS가 인간-기계 상호작용에서 추구하는 중요한 방향입니다. 즉, "기능 조작"에서 "의도 표현"으로 점진적으로 전환하는 것입니다.

물론 시스템이 능동적으로 작업을 완료한다고 해서 사용자가 아무것도 신경 쓸 필요가 없다는 의미는 아닙니다.

오히려 BlueOS AgentOS의 설계에서는 "능동적 실행"과 "사용자 제어 가능성"이 완벽하게 공존합니다. vivo는 이를 위해 "세 화면 연동" 상호작용 경험을 제공합니다. 이 중 대화 센터는 사용자가 의도를 표현하고 최종 결과를 받는 주요 입구입니다.

  • 사용자는 음성, 텍스트, 이미지, 파일 등 자연스러운 방식으로 시스템에 자신이 무엇을 하고 싶은지 직접 전달할 수 있습니다.
  • 예를 들어, 사용자가 "다음 주 베이징 출장 전체 일정을 계획해 줘."라고 말하면, 시스템은 실제로 실행을 시작하기 전에 작업에 필요한 권한(예: 일정 읽기, 웹 검색, 출장 앱 액세스 등)을 먼저 정리하고, 사용자에게 일괄적으로 승인을 요청합니다.
  • 사용자가 확인하면 Agent는 백그라운드에서 자율적으로 진행하여 가격 비교, 일정 확인, 계획 수립 등을 수행하며, 사용자는 현재 페이지에 머물러 기다릴 필요가 없습니다. 작업이 완료되면 최종 일정표는 대화 센터로 직접 전달됩니다.
  • 이렇게 되면 사용자가 보는 것은 더 이상 여러 앱을 오가는 복잡한 작업이 아니라, "요구 사항 제시 - 권한 확인 - 결과 대기 - 완성품 수령"이라는 극도로 간소화된 과정입니다.
  • 대화 센터를 오른쪽으로 스와이프하면 작업 센터로 진입합니다. 여기에는 결정 대기 중, 진행 중, 완료된 모든 작업이 집중적으로 표시됩니다. 사용자에게는 마치 "작업 진행 상황 전체 보기"와 같아서, 시스템이 현재 무엇을 하고 있는지, 어느 단계까지 진행되었는지, 자신의 확인이 필요한지 등을 한눈에 알 수 있습니다.
  • 만약 도중에 요구 사항이 변경되면, 사용자는 언제든지 작업을 개입, 조정 또는 중단할 수 있습니다.
  • 대화 센터를 왼쪽으로 스와이프하면 애플리케이션 센터로 진입합니다. 이 부분은 Agent의 등장으로 인해 기존 아이콘을 모두 버리지 않았습니다. 전화 걸기, 사진 촬영 등 목표가 매우 명확하고 조작 경로가 매우 짧은 고빈도 기능의 경우, 아이콘을 직접 클릭하는 것이 여전히 가장 효율적이므로 기존 애플리케이션 입구가 합리적으로 유지됩니다.
  • 세 화면은 각기 다른 역할을 합니다. 대화 센터는 의도 표현을 담당하고, 작업 센터는 과정을 명확히 보여주며, 애플리케이션 센터는 기존의 고빈도 작업을 유지합니다. 소비자에게는 이것이 AgentOS의 가장 직관적인 경험 변화일 것입니다. 휴대폰은 여전히 예전처럼 사용할 수 있지만, 작업이 번거롭고 복잡해지면 과정을 시스템에 안심하고 맡길 수 있습니다.

BlueOS Harness 시스템 수준 기반

앞서 언급된 유려한 경험은 시스템에 채팅 창 하나를 추가하고 대규모 언어 모델을 연결하는 것만으로는 결코 실현될 수 없습니다. 만약 기존의 앱 형태에만 의존한다면, AI는 종종 단일 애플리케이션 내에서만 "맴돌며", 애플리케이션 간 데이터 장벽, 백그라운드 유지의 어려움, 장치 간 협업의 약점 등 수많은 시스템 수준의 병목 현상에 직면하게 됩니다.

AI가 경계를 넘어 "여러 지역 출장 총괄 계획" 또는 "장치 간 전문 도구 스케줄링"과 같이 주기가 길고 관련 노드가 많은 복잡한 작업을 자율적으로 완료하게 하려면, 운영체제는 하위 실행 논리를 재구성해야 합니다.

이를 위해 BlueOS AgentOS의 핵심 기술 돌파는 Harness(Agent 실행 기반)를 시스템과 깊이 통합하여 BlueOS Harness 시스템 수준 기반을 구축하는 데 있습니다. 이는 기존의 앱을 경계로 하는 자원 스케줄링 방식을 깨고, 작업이 처음부터 끝까지, 애플리케이션과 장치를 넘나들며 안정적으로 실행되도록 합니다.

이 시스템 수준 기반은 다섯 가지 핵심 모듈의 깊은 협력으로 간단히 이해할 수 있습니다.

  • 첫 번째는 컨텍스트 엔진입니다.

    AI의 이전 "기억"은 단순히 정보를 저장하는 것이었지만, 기억하는 것이 현재 요구 사항을 이해하는 것과 같지는 않습니다. 예를 들어, 시스템에 출장을 계획하라고 요청하면, 시스템은 사용자가 어디를 방문했는지 아는 것뿐만 아니라, 내일의 일정 회의, 선호하는 항공편 시간 및 현재 장치 상태를 정확하게 파악해야 합니다. 컨텍스트 엔진은 선호도, 기록 및 현재 환경을 종합하여 작업에 진정으로 유용한 정보를 동적으로 매칭합니다. 동시에, 필요에 따라 정보를 읽어 무관한 개인 정보의 무단 액세스를 엄격히 방지합니다.

  • 두 번째는 작업 엔진입니다.

    이는 주로 Agent가 직면하는 "실행이 쉽게 중단되고, 장기적으로 진행할 수 없는" 문제점을 해결하는 데 사용됩니다. BlueOS AgentOS는 작업의 분해, 실행 및 검증을 분리합니다. 더 중요한 것은 작업 상태의 영구 저장을 지원한다는 것입니다. 며칠에 걸친 복잡한 작업 도중에 네트워크 연결이 끊기거나 도구에 이상이 발생하더라도, 시스템은 "어느 단계까지 진행되었는지"를 정확히 기억하고, 복구 후 계속 진행하며, 기계적으로 처음부터 다시 시작하지 않습니다.

  • 세 번째는 능력 버스입니다.

    이는 "교차 영역 스케줄링"의 난제를 해결합니다. 미래의 완전한 작업은 여러 장치 협업을 필요로 할 수 있습니다. 예를 들어, 고객 방문을 준비하려면 휴대폰의 이메일, PC의 전문 문서, 그리고 시계의 실시간 알림을 연동해야 합니다. 능력 버스는 하드웨어와 소프트웨어의 고립을 완전히 깨고, 휴대폰, 시계, PC 및 클라우드에 분산된 능력을 통합적으로 연결하며, 작업 요구 사항에 따라 가장 적합한 장치를 자동으로 선택하여 실행합니다.

  • 네 번째는 실행 환경 및 샌드박스입니다.

    Agent가 진정한 "생산성"을 갖추도록, 특히 사무실 및 개발 시나리오에 대응하기 위해 BlueOS는 기존 모바일 단말의 제한을 넘어 표준화된 Linux 실행 환경을 제공하고, 다른 작업을 독립적인 샌드박스로 격리합니다. 이는 Agent가 간단한 인터페이스를 호출할 수 있을 뿐만 아니라, Python, Shell 등의 구성 요소를 안전하고 안정적으로 실행하고, 심지어 성숙한 개발자 도구 체인을 사용할 수 있음을 의미합니다.

  • 다섯 번째는 보안 거버넌스 시스템입니다.

    능력이 강해질수록 경계는 더욱 명확해야 합니다.

    AI가 "질문에 답하는" 수준에서 사용자 대신 이메일을 보내고, 민감한 파일을 읽고, 심지어 장치 간 작업을 수행할 수 있는 수준으로 진화할 때, "무엇을 할 수 있는지"와 "무엇을 해야 하는지"에 대한 명확한 보안 정책이 필요합니다. BlueOS AgentOS는 최소 필요 원칙을 강조합니다. 작업 시작 전 목표와 권한 경계를 명확히 하고, 실행 중 민감한 데이터 액세스를 엄격히 제어하며, 핵심 애플리케이션 간 작업은 전체 과정을 기록하고 추적 가능하도록 합니다.

    더 중요한 것은 사용자가 항상 최종 결정권을 보유한다는 것입니다. 간단히 말해, Agent는 사용자 대신 실행할 수 있지만, 사용자 대신 모든 것을 결정할 수는 없습니다.

BlueOS AgentOS의 응용 시나리오

시스템이 하위 능력을 통합하면 BlueOS AgentOS의 응용 시나리오는 매우 상상력이 풍부해집니다.

이번 기술 프리뷰에서는 오피스 Agent와 코딩 Agent가 주목할 만한 두 가지 방향입니다. 오피스 Agent는 언제든지 호출할 수 있는 모바일 오피스 파트너와 같습니다. 문서, 회의록, 데이터 자료 등의 내용에 대해 사용자는 직접 단계별로 정리할 필요 없이, 목표를 직접 설명하면 Agent가 작업을 분해하고, 도구를 호출하며, 결과를 전달합니다.

코딩 Agent는 더욱 직접적입니다.

기존 코딩은 종종 컴퓨터 없이는 불가능했지만, BlueOS AgentOS는 이러한 능력을 모바일 단말로 더욱 확장합니다. 개발자는 음성, 텍스트, 심지어 이미지를 통해 자신의 요구 사항을 설명할 수 있으며, Agent는 단말에서 코드를 생성하고, 컴파일 환경을 호출하며, 프로그램을 실행하고, 실제 장치에서 미리 보고 검증합니다.

  • 개발자에게는 "휴대용 작업 파트너"가 될 수 있습니다. 잠시 컴퓨터를 떠나더라도 코드 수정, 문제 해결 및 일부 On-Call 작업을 처리할 수 있습니다.
  • 일반 사용자에게는 "주머니 속 생활 파트너"로 이해할 수 있습니다. 미래에는 복잡한 개발 도구를 먼저 배울 필요 없이, 자신의 요구 사항을 명확하게 설명할 수 있다면 시스템이 간단한 앱이나 자동화 도구를 생성할 기회를 가질 수 있습니다.

물론 이러한 능력은 현재 기술 탐색 및 프리뷰 단계에 있지만, 이는 엄청난 상상력을 발휘하며 미래를 기대하게 합니다.

BlueOS의 발전 과정

시간을 길게 보면, BlueOS AgentOS는 사실 물 흐르듯 자연스럽게 축적된 결과입니다.

  • 2018년 일찍이 BlueOS는 관련 연구 개발을 시작했습니다.
  • 2023년, BlueOS가 공식 발표되었고, vivo WATCH 3에 처음 탑재되었습니다.
  • 2024년, BlueOS 2가 발표되어 풀 스택 Rust 기술 로드맵을 더욱 추진하고, 자체 개발한 Rust BlueOS 커널을 추가했습니다.
  • 2025년, BlueOS 커널이 공식적으로 오픈 소스화되었고, Open Atom Open Source Foundation의 BlueKernel 인큐베이션 프로젝트가 되어 더욱 개방적인 공동 구축 단계에 진입했습니다.

BlueOS 발표 이후, BlueOS의 기술 로드맵도 지속적으로 발전해 왔습니다. 커널, 시스템 프레임워크부터 단말 AI에 이르기까지 지난 몇 년간의 축적이 오늘날 AgentOS 탐색의 기반을 형성했습니다. 이 4년간의 기반 덕분에 BlueOS는 "경계를 넘는" 데 성공했습니다.

과거 BlueOS의 적용 범위는 주로 스마트워치와 같은 IoT 장치에 집중되었습니다. 이번 AgentOS 기술 프리뷰는 BlueOS가 더 복잡한 단말 시나리오로 확장될 가능성을 보여주었습니다. 휴대폰에서의 작업 실행, 단말 코딩, 또는 휴대폰, 시계, PC 및 클라우드 간의 능력 스케줄링 등 모두 BlueOS가 기존 시스템 능력을 더 많은 장치와 사용 시나리오로 확장하려 시도하고 있음을 보여줍니다.

총평

vivo는 하위 기술력을 과시하며 업계의 질문에 답하고자 합니다. AI가 "대화"에서 "작업 수행"으로 진화할 때, 미래의 운영체제는 어떤 모습이어야 할까요? BlueOS AgentOS의 답은 "사용자와 디지털 세계를 연결하는 '슈퍼 작업 허브'가 되는 것"입니다.

이는 인간-기계 상호작용의 논리를 재정의할 것입니다. 사용자에게는 "앱 찾기, 버튼 클릭"에서 "목표 지시, 시스템 결과 제출"로 작업 방식이 변화하고, 개발자에게는 자신의 서비스가 Agent에 의해 즉시 이해되고 호출되도록 하는 것이 AI 시대의 새로운 입구를 선점하는 핵심이 될 것입니다.

BlueOS AgentOS의 이번 등장은 AGI 시대를 향한 첨단 기술의 예고편에 가깝지만, 이 강력한 시연을 통해 vivo는 차세대 운영체제의 진화 방향을 미래에 명확하게 제시했습니다.

서론

2022년 생성형 AI의 물결이 시작된 이래, 사람들은 AI의 강력한 "대화 및 질의응답" 능력에 처음으로 주목했습니다.

하지만 올해 들어 Agent의 빠른 발전과 함께 업계의 초점은 실질적으로 변화하고 있습니다. AI는 더 이상 조언만 제공하는 것이 아니라, 사용자 대신 직접 일을 처리합니다.

이는 AI가 더 이상 단순한 질의응답 문제에 직면하는 것이 아님을 의미합니다. AI는 시나리오를 인지하고, 복잡한 목표를 분해하며, 도구를 자율적으로 호출하고, 예외 상황 발생 시 처리 방법과 결과 검증 방법을 알아야 합니다.

이러한 이유로 업계의 기술적 중심은 "Harness 엔지니어링"으로 발전하기 시작했습니다.

간단히 말해, 대규모 언어 모델을 사고를 담당하는 "두뇌"에 비유한다면, Harness는 이 두뇌가 실제로 작동하도록 하는 "작업 기반"이며, AI가 "답변할 수 있는" 수준에서 "실행하고, 지속하며, 검증할 수 있는" 수준으로 도약하게 합니다.

그러나 AI가 실제로 애플리케이션 간 작업을 실행하기 시작하면, 필연적으로 하위 권한 관리, 데이터 액세스 및 장치 스케줄링에 접하게 됩니다. 이는 분명히 단일 앱이 제어할 수 있는 범위를 넘어섭니다.

따라서 운영체제는 Agent 시대의 새로운 인프라가 되는 것이 당연합니다.

이러한 기술 발전에 발맞춰 vivo는 자체 개발한 BlueOS를 기반으로 AGI 시대를 위한 AgentOS 탐색을 공식적으로 시작했습니다.

핵심은 Agent Harness(Agent 실행 기반)를 운영체제에 깊이 통합하여 시스템 코어에 전용 Agent 프레임워크를 구축하고, 시스템이 의도 이해, 작업 계획, 도구 스케줄링 등의 기능을 기본적으로 갖추도록 하는 것입니다.

이는 BlueOS가 탄생 초기부터 가졌던 포지셔닝, 즉 vivo가 AGI 시대를 위해 자체 개발한 지능형 운영체제와도 일맥상통합니다.

BlueOS 4-AgentOS 기술 프리뷰 발표

9월 16일, 2026 vivo 개발자 컨퍼런스가 선전에서 개최되었습니다.

vivo는 BlueOS 4-AgentOS 기술 프리뷰(이하 BlueOS AgentOS)를 공식 발표했습니다. 이는 Agent 시대를 위한 시스템 수준의 탐색으로, 핵심은 한 문장으로 요약할 수 있습니다. "인간-기계 상호작용, 시스템 아키텍처, 애플리케이션 생태계를 지속적으로 심화하고, '작업 중심'에 초점을 맞춰 사용자를 이해하고, 장치를 이해하며, 작업을 수행할 수 있는 지능형 경험을 구축합니다."

인간-기계 상호작용의 변화

기존 휴대폰 사용 논리는 매우 고정적입니다. 배달을 주문하려면 배달 앱을 열고, 항공권을 조회하려면 여행 앱을 열고, PPT를 만들려면 오피스 소프트웨어를 열고, 데이터를 처리하려면 스프레드시트 도구를 찾아야 합니다.

사용자는 "어떤 일에 어떤 앱을 사용해야 하는지" 스스로 기억하고, 다른 애플리케이션 간에 전환해야 합니다.

AgentOS는 이러한 복잡한 작업을 시스템에 맡깁니다. 사용자는 "어떤 앱을 열어야 할까"를 먼저 생각할 필요 없이, 자신이 무엇을 하고 싶은지 직접 말합니다. 예를 들어, "오늘 회의 내용을 보고서 PPT로 정리해 줘."라고 말하면, 시스템은 이 목표를 이해한 후 회의 기록을 찾아보고, 관련 프로젝트 자료를 읽고, 해당 도구를 호출하여 내용을 정리한 다음 최종 결과를 사용자에게 전달할 수 있습니다.

이것이 BlueOS AgentOS가 인간-기계 상호작용에서 추구하는 중요한 방향입니다. 즉, "기능 조작"에서 "의도 표현"으로 점진적으로 전환하는 것입니다.

물론 시스템이 능동적으로 작업을 완료한다고 해서 사용자가 아무것도 신경 쓸 필요가 없다는 의미는 아닙니다.

오히려 BlueOS AgentOS의 설계에서는 "능동적 실행"과 "사용자 제어 가능성"이 완벽하게 공존합니다. vivo는 이를 위해 "세 화면 연동" 상호작용 경험을 제공합니다. 이 중 대화 센터는 사용자가 의도를 표현하고 최종 결과를 받는 주요 입구입니다.

  • 사용자는 음성, 텍스트, 이미지, 파일 등 자연스러운 방식으로 시스템에 자신이 무엇을 하고 싶은지 직접 전달할 수 있습니다.
  • 예를 들어, 사용자가 "다음 주 베이징 출장 전체 일정을 계획해 줘."라고 말하면, 시스템은 실제로 실행을 시작하기 전에 작업에 필요한 권한(예: 일정 읽기, 웹 검색, 출장 앱 액세스 등)을 먼저 정리하고, 사용자에게 일괄적으로 승인을 요청합니다.
  • 사용자가 확인하면 Agent는 백그라운드에서 자율적으로 진행하여 가격 비교, 일정 확인, 계획 수립 등을 수행하며, 사용자는 현재 페이지에 머물러 기다릴 필요가 없습니다. 작업이 완료되면 최종 일정표는 대화 센터로 직접 전달됩니다.
  • 이렇게 되면 사용자가 보는 것은 더 이상 여러 앱을 오가는 복잡한 작업이 아니라, "요구 사항 제시 - 권한 확인 - 결과 대기 - 완성품 수령"이라는 극도로 간소화된 과정입니다.
  • 대화 센터를 오른쪽으로 스와이프하면 작업 센터로 진입합니다. 여기에는 결정 대기 중, 진행 중, 완료된 모든 작업이 집중적으로 표시됩니다. 사용자에게는 마치 "작업 진행 상황 전체 보기"와 같아서, 시스템이 현재 무엇을 하고 있는지, 어느 단계까지 진행되었는지, 자신의 확인이 필요한지 등을 한눈에 알 수 있습니다.
  • 만약 도중에 요구 사항이 변경되면, 사용자는 언제든지 작업을 개입, 조정 또는 중단할 수 있습니다.
  • 대화 센터를 왼쪽으로 스와이프하면 애플리케이션 센터로 진입합니다. 이 부분은 Agent의 등장으로 인해 기존 아이콘을 모두 버리지 않았습니다. 전화 걸기, 사진 촬영 등 목표가 매우 명확하고 조작 경로가 매우 짧은 고빈도 기능의 경우, 아이콘을 직접 클릭하는 것이 여전히 가장 효율적이므로 기존 애플리케이션 입구가 합리적으로 유지됩니다.
  • 세 화면은 각기 다른 역할을 합니다. 대화 센터는 의도 표현을 담당하고, 작업 센터는 과정을 명확히 보여주며, 애플리케이션 센터는 기존의 고빈도 작업을 유지합니다. 소비자에게는 이것이 AgentOS의 가장 직관적인 경험 변화일 것입니다. 휴대폰은 여전히 예전처럼 사용할 수 있지만, 작업이 번거롭고 복잡해지면 과정을 시스템에 안심하고 맡길 수 있습니다.

BlueOS Harness 시스템 수준 기반

앞서 언급된 유려한 경험은 시스템에 채팅 창 하나를 추가하고 대규모 언어 모델을 연결하는 것만으로는 결코 실현될 수 없습니다. 만약 기존의 앱 형태에만 의존한다면, AI는 종종 단일 애플리케이션 내에서만 "맴돌며", 애플리케이션 간 데이터 장벽, 백그라운드 유지의 어려움, 장치 간 협업의 약점 등 수많은 시스템 수준의 병목 현상에 직면하게 됩니다.

AI가 경계를 넘어 "여러 지역 출장 총괄 계획" 또는 "장치 간 전문 도구 스케줄링"과 같이 주기가 길고 관련 노드가 많은 복잡한 작업을 자율적으로 완료하게 하려면, 운영체제는 하위 실행 논리를 재구성해야 합니다.

이를 위해 BlueOS AgentOS의 핵심 기술 돌파는 Harness(Agent 실행 기반)를 시스템과 깊이 통합하여 BlueOS Harness 시스템 수준 기반을 구축하는 데 있습니다. 이는 기존의 앱을 경계로 하는 자원 스케줄링 방식을 깨고, 작업이 처음부터 끝까지, 애플리케이션과 장치를 넘나들며 안정적으로 실행되도록 합니다.

이 시스템 수준 기반은 다섯 가지 핵심 모듈의 깊은 협력으로 간단히 이해할 수 있습니다.

  • 첫 번째는 컨텍스트 엔진입니다.

    AI의 이전 "기억"은 단순히 정보를 저장하는 것이었지만, 기억하는 것이 현재 요구 사항을 이해하는 것과 같지는 않습니다. 예를 들어, 시스템에 출장을 계획하라고 요청하면, 시스템은 사용자가 어디를 방문했는지 아는 것뿐만 아니라, 내일의 일정 회의, 선호하는 항공편 시간 및 현재 장치 상태를 정확하게 파악해야 합니다. 컨텍스트 엔진은 선호도, 기록 및 현재 환경을 종합하여 작업에 진정으로 유용한 정보를 동적으로 매칭합니다. 동시에, 필요에 따라 정보를 읽어 무관한 개인 정보의 무단 액세스를 엄격히 방지합니다.

  • 두 번째는 작업 엔진입니다.

    이는 주로 Agent가 직면하는 "실행이 쉽게 중단되고, 장기적으로 진행할 수 없는" 문제점을 해결하는 데 사용됩니다. BlueOS AgentOS는 작업의 분해, 실행 및 검증을 분리합니다. 더 중요한 것은 작업 상태의 영구 저장을 지원한다는 것입니다. 며칠에 걸친 복잡한 작업 도중에 네트워크 연결이 끊기거나 도구에 이상이 발생하더라도, 시스템은 "어느 단계까지 진행되었는지"를 정확히 기억하고, 복구 후 계속 진행하며, 기계적으로 처음부터 다시 시작하지 않습니다.

  • 세 번째는 능력 버스입니다.

    이는 "교차 영역 스케줄링"의 난제를 해결합니다. 미래의 완전한 작업은 여러 장치 협업을 필요로 할 수 있습니다. 예를 들어, 고객 방문을 준비하려면 휴대폰의 이메일, PC의 전문 문서, 그리고 시계의 실시간 알림을 연동해야 합니다. 능력 버스는 하드웨어와 소프트웨어의 고립을 완전히 깨고, 휴대폰, 시계, PC 및 클라우드에 분산된 능력을 통합적으로 연결하며, 작업 요구 사항에 따라 가장 적합한 장치를 자동으로 선택하여 실행합니다.

  • 네 번째는 실행 환경 및 샌드박스입니다.

    Agent가 진정한 "생산성"을 갖추도록, 특히 사무실 및 개발 시나리오에 대응하기 위해 BlueOS는 기존 모바일 단말의 제한을 넘어 표준화된 Linux 실행 환경을 제공하고, 다른 작업을 독립적인 샌드박스로 격리합니다. 이는 Agent가 간단한 인터페이스를 호출할 수 있을 뿐만 아니라, Python, Shell 등의 구성 요소를 안전하고 안정적으로 실행하고, 심지어 성숙한 개발자 도구 체인을 사용할 수 있음을 의미합니다.

  • 다섯 번째는 보안 거버넌스 시스템입니다.

    능력이 강해질수록 경계는 더욱 명확해야 합니다.

    AI가 "질문에 답하는" 수준에서 사용자 대신 이메일을 보내고, 민감한 파일을 읽고, 심지어 장치 간 작업을 수행할 수 있는 수준으로 진화할 때, "무엇을 할 수 있는지"와 "무엇을 해야 하는지"에 대한 명확한 보안 정책이 필요합니다. BlueOS AgentOS는 최소 필요 원칙을 강조합니다. 작업 시작 전 목표와 권한 경계를 명확히 하고, 실행 중 민감한 데이터 액세스를 엄격히 제어하며, 핵심 애플리케이션 간 작업은 전체 과정을 기록하고 추적 가능하도록 합니다.

    더 중요한 것은 사용자가 항상 최종 결정권을 보유한다는 것입니다. 간단히 말해, Agent는 사용자 대신 실행할 수 있지만, 사용자 대신 모든 것을 결정할 수는 없습니다.

BlueOS AgentOS의 응용 시나리오

시스템이 하위 능력을 통합하면 BlueOS AgentOS의 응용 시나리오는 매우 상상력이 풍부해집니다.

이번 기술 프리뷰에서는 오피스 Agent와 코딩 Agent가 주목할 만한 두 가지 방향입니다. 오피스 Agent는 언제든지 호출할 수 있는 모바일 오피스 파트너와 같습니다. 문서, 회의록, 데이터 자료 등의 내용에 대해 사용자는 직접 단계별로 정리할 필요 없이, 목표를 직접 설명하면 Agent가 작업을 분해하고, 도구를 호출하며, 결과를 전달합니다.

코딩 Agent는 더욱 직접적입니다.

기존 코딩은 종종 컴퓨터 없이는 불가능했지만, BlueOS AgentOS는 이러한 능력을 모바일 단말로 더욱 확장합니다. 개발자는 음성, 텍스트, 심지어 이미지를 통해 자신의 요구 사항을 설명할 수 있으며, Agent는 단말에서 코드를 생성하고, 컴파일 환경을 호출하며, 프로그램을 실행하고, 실제 장치에서 미리 보고 검증합니다.

  • 개발자에게는 "휴대용 작업 파트너"가 될 수 있습니다. 잠시 컴퓨터를 떠나더라도 코드 수정, 문제 해결 및 일부 On-Call 작업을 처리할 수 있습니다.
  • 일반 사용자에게는 "주머니 속 생활 파트너"로 이해할 수 있습니다. 미래에는 복잡한 개발 도구를 먼저 배울 필요 없이, 자신의 요구 사항을 명확하게 설명할 수 있다면 시스템이 간단한 앱이나 자동화 도구를 생성할 기회를 가질 수 있습니다.

물론 이러한 능력은 현재 기술 탐색 및 프리뷰 단계에 있지만, 이는 엄청난 상상력을 발휘하며 미래를 기대하게 합니다.

BlueOS의 발전 과정

시간을 길게 보면, BlueOS AgentOS는 사실 물 흐르듯 자연스럽게 축적된 결과입니다.

  • 2018년 일찍이 BlueOS는 관련 연구 개발을 시작했습니다.
  • 2023년, BlueOS가 공식 발표되었고, vivo WATCH 3에 처음 탑재되었습니다.
  • 2024년, BlueOS 2가 발표되어 풀 스택 Rust 기술 로드맵을 더욱 추진하고, 자체 개발한 Rust BlueOS 커널을 추가했습니다.
  • 2025년, BlueOS 커널이 공식적으로 오픈 소스화되었고, Open Atom Open Source Foundation의 BlueKernel 인큐베이션 프로젝트가 되어 더욱 개방적인 공동 구축 단계에 진입했습니다.

BlueOS 발표 이후, BlueOS의 기술 로드맵도 지속적으로 발전해 왔습니다. 커널, 시스템 프레임워크부터 단말 AI에 이르기까지 지난 몇 년간의 축적이 오늘날 AgentOS 탐색의 기반을 형성했습니다. 이 4년간의 기반 덕분에 BlueOS는 "경계를 넘는" 데 성공했습니다.

과거 BlueOS의 적용 범위는 주로 스마트워치와 같은 IoT 장치에 집중되었습니다. 이번 AgentOS 기술 프리뷰는 BlueOS가 더 복잡한 단말 시나리오로 확장될 가능성을 보여주었습니다. 휴대폰에서의 작업 실행, 단말 코딩, 또는 휴대폰, 시계, PC 및 클라우드 간의 능력 스케줄링 등 모두 BlueOS가 기존 시스템 능력을 더 많은 장치와 사용 시나리오로 확장하려 시도하고 있음을 보여줍니다.

총평

vivo는 하위 기술력을 과시하며 업계의 질문에 답하고자 합니다. AI가 "대화"에서 "작업 수행"으로 진화할 때, 미래의 운영체제는 어떤 모습이어야 할까요? BlueOS AgentOS의 답은 "사용자와 디지털 세계를 연결하는 '슈퍼 작업 허브'가 되는 것"입니다.

이는 인간-기계 상호작용의 논리를 재정의할 것입니다. 사용자에게는 "앱 찾기, 버튼 클릭"에서 "목표 지시, 시스템 결과 제출"로 작업 방식이 변화하고, 개발자에게는 자신의 서비스가 Agent에 의해 즉시 이해되고 호출되도록 하는 것이 AI 시대의 새로운 입구를 선점하는 핵심이 될 것입니다.

BlueOS AgentOS의 이번 등장은 AGI 시대를 향한 첨단 기술의 예고편에 가깝지만, 이 강력한 시연을 통해 vivo는 차세대 운영체제의 진화 방향을 미래에 명확하게 제시했습니다.

서론

2022년 생성형 AI의 물결이 시작된 이래, 사람들은 AI의 강력한 "대화 및 질의응답" 능력에 처음으로 주목했습니다.

하지만 올해 들어 Agent의 빠른 발전과 함께 업계의 초점은 실질적으로 변화하고 있습니다. AI는 더 이상 조언만 제공하는 것이 아니라, 사용자 대신 직접 일을 처리합니다.

이는 AI가 더 이상 단순한 질의응답 문제에 직면하는 것이 아님을 의미합니다. AI는 시나리오를 인지하고, 복잡한 목표를 분해하며, 도구를 자율적으로 호출하고, 예외 상황 발생 시 처리 방법과 결과 검증 방법을 알아야 합니다.

이러한 이유로 업계의 기술적 중심은 "Harness 엔지니어링"으로 발전하기 시작했습니다.

간단히 말해, 대규모 언어 모델을 사고를 담당하는 "두뇌"에 비유한다면, Harness는 이 두뇌가 실제로 작동하도록 하는 "작업 기반"이며, AI가 "답변할 수 있는" 수준에서 "실행하고, 지속하며, 검증할 수 있는" 수준으로 도약하게 합니다.

그러나 AI가 실제로 애플리케이션 간 작업을 실행하기 시작하면, 필연적으로 하위 권한 관리, 데이터 액세스 및 장치 스케줄링에 접하게 됩니다. 이는 분명히 단일 앱이 제어할 수 있는 범위를 넘어섭니다.

따라서 운영체제는 Agent 시대의 새로운 인프라가 되는 것이 당연합니다.

이러한 기술 발전에 발맞춰 vivo는 자체 개발한 BlueOS를 기반으로 AGI 시대를 위한 AgentOS 탐색을 공식적으로 시작했습니다.

핵심은 Agent Harness(Agent 실행 기반)를 운영체제에 깊이 통합하여 시스템 코어에 전용 Agent 프레임워크를 구축하고, 시스템이 의도 이해, 작업 계획, 도구 스케줄링 등의 기능을 기본적으로 갖추도록 하는 것입니다.

이는 BlueOS가 탄생 초기부터 가졌던 포지셔닝, 즉 vivo가 AGI 시대를 위해 자체 개발한 지능형 운영체제와도 일맥상통합니다.

BlueOS 4-AgentOS 기술 프리뷰 발표

9월 16일, 2026 vivo 개발자 컨퍼런스가 선전에서 개최되었습니다.

vivo는 BlueOS 4-AgentOS 기술 프리뷰(이하 BlueOS AgentOS)를 공식 발표했습니다. 이는 Agent 시대를 위한 시스템 수준의 탐색으로, 핵심은 한 문장으로 요약할 수 있습니다. "인간-기계 상호작용, 시스템 아키텍처, 애플리케이션 생태계를 지속적으로 심화하고, '작업 중심'에 초점을 맞춰 사용자를 이해하고, 장치를 이해하며, 작업을 수행할 수 있는 지능형 경험을 구축합니다."

인간-기계 상호작용의 변화

기존 휴대폰 사용 논리는 매우 고정적입니다. 배달을 주문하려면 배달 앱을 열고, 항공권을 조회하려면 여행 앱을 열고, PPT를 만들려면 오피스 소프트웨어를 열고, 데이터를 처리하려면 스프레드시트 도구를 찾아야 합니다.

사용자는 "어떤 일에 어떤 앱을 사용해야 하는지" 스스로 기억하고, 다른 애플리케이션 간에 전환해야 합니다.

AgentOS는 이러한 복잡한 작업을 시스템에 맡깁니다. 사용자는 "어떤 앱을 열어야 할까"를 먼저 생각할 필요 없이, 자신이 무엇을 하고 싶은지 직접 말합니다. 예를 들어, "오늘 회의 내용을 보고서 PPT로 정리해 줘."라고 말하면, 시스템은 이 목표를 이해한 후 회의 기록을 찾아보고, 관련 프로젝트 자료를 읽고, 해당 도구를 호출하여 내용을 정리한 다음 최종 결과를 사용자에게 전달할 수 있습니다.

이것이 BlueOS AgentOS가 인간-기계 상호작용에서 추구하는 중요한 방향입니다. 즉, "기능 조작"에서 "의도 표현"으로 점진적으로 전환하는 것입니다.

물론 시스템이 능동적으로 작업을 완료한다고 해서 사용자가 아무것도 신경 쓸 필요가 없다는 의미는 아닙니다.

오히려 BlueOS AgentOS의 설계에서는 "능동적 실행"과 "사용자 제어 가능성"이 완벽하게 공존합니다. vivo는 이를 위해 "세 화면 연동" 상호작용 경험을 제공합니다. 이 중 대화 센터는 사용자가 의도를 표현하고 최종 결과를 받는 주요 입구입니다.

  • 사용자는 음성, 텍스트, 이미지, 파일 등 자연스러운 방식으로 시스템에 자신이 무엇을 하고 싶은지 직접 전달할 수 있습니다.
  • 예를 들어, 사용자가 "다음 주 베이징 출장 전체 일정을 계획해 줘."라고 말하면, 시스템은 실제로 실행을 시작하기 전에 작업에 필요한 권한(예: 일정 읽기, 웹 검색, 출장 앱 액세스 등)을 먼저 정리하고, 사용자에게 일괄적으로 승인을 요청합니다.
  • 사용자가 확인하면 Agent는 백그라운드에서 자율적으로 진행하여 가격 비교, 일정 확인, 계획 수립 등을 수행하며, 사용자는 현재 페이지에 머물러 기다릴 필요가 없습니다. 작업이 완료되면 최종 일정표는 대화 센터로 직접 전달됩니다.
  • 이렇게 되면 사용자가 보는 것은 더 이상 여러 앱을 오가는 복잡한 작업이 아니라, "요구 사항 제시 - 권한 확인 - 결과 대기 - 완성품 수령"이라는 극도로 간소화된 과정입니다.
  • 대화 센터를 오른쪽으로 스와이프하면 작업 센터로 진입합니다. 여기에는 결정 대기 중, 진행 중, 완료된 모든 작업이 집중적으로 표시됩니다. 사용자에게는 마치 "작업 진행 상황 전체 보기"와 같아서, 시스템이 현재 무엇을 하고 있는지, 어느 단계까지 진행되었는지, 자신의 확인이 필요한지 등을 한눈에 알 수 있습니다.
  • 만약 도중에 요구 사항이 변경되면, 사용자는 언제든지 작업을 개입, 조정 또는 중단할 수 있습니다.
  • 대화 센터를 왼쪽으로 스와이프하면 애플리케이션 센터로 진입합니다. 이 부분은 Agent의 등장으로 인해 기존 아이콘을 모두 버리지 않았습니다. 전화 걸기, 사진 촬영 등 목표가 매우 명확하고 조작 경로가 매우 짧은 고빈도 기능의 경우, 아이콘을 직접 클릭하는 것이 여전히 가장 효율적이므로 기존 애플리케이션 입구가 합리적으로 유지됩니다.
  • 세 화면은 각기 다른 역할을 합니다. 대화 센터는 의도 표현을 담당하고, 작업 센터는 과정을 명확히 보여주며, 애플리케이션 센터는 기존의 고빈도 작업을 유지합니다. 소비자에게는 이것이 AgentOS의 가장 직관적인 경험 변화일 것입니다. 휴대폰은 여전히 예전처럼 사용할 수 있지만, 작업이 번거롭고 복잡해지면 과정을 시스템에 안심하고 맡길 수 있습니다.

BlueOS Harness 시스템 수준 기반

앞서 언급된 유려한 경험은 시스템에 채팅 창 하나를 추가하고 대규모 언어 모델을 연결하는 것만으로는 결코 실현될 수 없습니다. 만약 기존의 앱 형태에만 의존한다면, AI는 종종 단일 애플리케이션 내에서만 "맴돌며", 애플리케이션 간 데이터 장벽, 백그라운드 유지의 어려움, 장치 간 협업의 약점 등 수많은 시스템 수준의 병목 현상에 직면하게 됩니다.

AI가 경계를 넘어 "여러 지역 출장 총괄 계획" 또는 "장치 간 전문 도구 스케줄링"과 같이 주기가 길고 관련 노드가 많은 복잡한 작업을 자율적으로 완료하게 하려면, 운영체제는 하위 실행 논리를 재구성해야 합니다.

이를 위해 BlueOS AgentOS의 핵심 기술 돌파는 Harness(Agent 실행 기반)를 시스템과 깊이 통합하여 BlueOS Harness 시스템 수준 기반을 구축하는 데 있습니다. 이는 기존의 앱을 경계로 하는 자원 스케줄링 방식을 깨고, 작업이 처음부터 끝까지, 애플리케이션과 장치를 넘나들며 안정적으로 실행되도록 합니다.

이 시스템 수준 기반은 다섯 가지 핵심 모듈의 깊은 협력으로 간단히 이해할 수 있습니다.

  • 첫 번째는 컨텍스트 엔진입니다.

    AI의 이전 "기억"은 단순히 정보를 저장하는 것이었지만, 기억하는 것이 현재 요구 사항을 이해하는 것과 같지는 않습니다. 예를 들어, 시스템에 출장을 계획하라고 요청하면, 시스템은 사용자가 어디를 방문했는지 아는 것뿐만 아니라, 내일의 일정 회의, 선호하는 항공편 시간 및 현재 장치 상태를 정확하게 파악해야 합니다. 컨텍스트 엔진은 선호도, 기록 및 현재 환경을 종합하여 작업에 진정으로 유용한 정보를 동적으로 매칭합니다. 동시에, 필요에 따라 정보를 읽어 무관한 개인 정보의 무단 액세스를 엄격히 방지합니다.

  • 두 번째는 작업 엔진입니다.

    이는 주로 Agent가 직면하는 "실행이 쉽게 중단되고, 장기적으로 진행할 수 없는" 문제점을 해결하는 데 사용됩니다. BlueOS AgentOS는 작업의 분해, 실행 및 검증을 분리합니다. 더 중요한 것은 작업 상태의 영구 저장을 지원한다는 것입니다. 며칠에 걸친 복잡한 작업 도중에 네트워크 연결이 끊기거나 도구에 이상이 발생하더라도, 시스템은 "어느 단계까지 진행되었는지"를 정확히 기억하고, 복구 후 계속 진행하며, 기계적으로 처음부터 다시 시작하지 않습니다.

  • 세 번째는 능력 버스입니다.

    이는 "교차 영역 스케줄링"의 난제를 해결합니다. 미래의 완전한 작업은 여러 장치 협업을 필요로 할 수 있습니다. 예를 들어, 고객 방문을 준비하려면 휴대폰의 이메일, PC의 전문 문서, 그리고 시계의 실시간 알림을 연동해야 합니다. 능력 버스는 하드웨어와 소프트웨어의 고립을 완전히 깨고, 휴대폰, 시계, PC 및 클라우드에 분산된 능력을 통합적으로 연결하며, 작업 요구 사항에 따라 가장 적합한 장치를 자동으로 선택하여 실행합니다.

  • 네 번째는 실행 환경 및 샌드박스입니다.

    Agent가 진정한 "생산성"을 갖추도록, 특히 사무실 및 개발 시나리오에 대응하기 위해 BlueOS는 기존 모바일 단말의 제한을 넘어 표준화된 Linux 실행 환경을 제공하고, 다른 작업을 독립적인 샌드박스로 격리합니다. 이는 Agent가 간단한 인터페이스를 호출할 수 있을 뿐만 아니라, Python, Shell 등의 구성 요소를 안전하고 안정적으로 실행하고, 심지어 성숙한 개발자 도구 체인을 사용할 수 있음을 의미합니다.

  • 다섯 번째는 보안 거버넌스 시스템입니다.

    능력이 강해질수록 경계는 더욱 명확해야 합니다.

    AI가 "질문에 답하는" 수준에서 사용자 대신 이메일을 보내고, 민감한 파일을 읽고, 심지어 장치 간 작업을 수행할 수 있는 수준으로 진화할 때, "무엇을 할 수 있는지"와 "무엇을 해야 하는지"에 대한 명확한 보안 정책이 필요합니다. BlueOS AgentOS는 최소 필요 원칙을 강조합니다. 작업 시작 전 목표와 권한 경계를 명확히 하고, 실행 중 민감한 데이터 액세스를 엄격히 제어하며, 핵심 애플리케이션 간 작업은 전체 과정을 기록하고 추적 가능하도록 합니다.

    더 중요한 것은 사용자가 항상 최종 결정권을 보유한다는 것입니다. 간단히 말해, Agent는 사용자 대신 실행할 수 있지만, 사용자 대신 모든 것을 결정할 수는 없습니다.

BlueOS AgentOS의 응용 시나리오

시스템이 하위 능력을 통합하면 BlueOS AgentOS의 응용 시나리오는 매우 상상력이 풍부해집니다.

이번 기술 프리뷰에서는 오피스 Agent와 코딩 Agent가 주목할 만한 두 가지 방향입니다. 오피스 Agent는 언제든지 호출할 수 있는 모바일 오피스 파트너와 같습니다. 문서, 회의록, 데이터 자료 등의 내용에 대해 사용자는 직접 단계별로 정리할 필요 없이, 목표를 직접 설명하면 Agent가 작업을 분해하고, 도구를 호출하며, 결과를 전달합니다.

코딩 Agent는 더욱 직접적입니다.

기존 코딩은 종종 컴퓨터 없이는 불가능했지만, BlueOS AgentOS는 이러한 능력을 모바일 단말로 더욱 확장합니다. 개발자는 음성, 텍스트, 심지어 이미지를 통해 자신의 요구 사항을 설명할 수 있으며, Agent는 단말에서 코드를 생성하고, 컴파일 환경을 호출하며, 프로그램을 실행하고, 실제 장치에서 미리 보고 검증합니다.

  • 개발자에게는 "휴대용 작업 파트너"가 될 수 있습니다. 잠시 컴퓨터를 떠나더라도 코드 수정, 문제 해결 및 일부 On-Call 작업을 처리할 수 있습니다.
  • 일반 사용자에게는 "주머니 속 생활 파트너"로 이해할 수 있습니다. 미래에는 복잡한 개발 도구를 먼저 배울 필요 없이, 자신의 요구 사항을 명확하게 설명할 수 있다면 시스템이 간단한 앱이나 자동화 도구를 생성할 기회를 가질 수 있습니다.

물론 이러한 능력은 현재 기술 탐색 및 프리뷰 단계에 있지만, 이는 엄청난 상상력을 발휘하며 미래를 기대하게 합니다.

BlueOS의 발전 과정

시간을 길게 보면, BlueOS AgentOS는 사실 물 흐르듯 자연스럽게 축적된 결과입니다.

  • 2018년 일찍이 BlueOS는 관련 연구 개발을 시작했습니다.
  • 2023년, BlueOS가 공식 발표되었고, vivo WATCH 3에 처음 탑재되었습니다.
  • 2024년, BlueOS 2가 발표되어 풀 스택 Rust 기술 로드맵을 더욱 추진하고, 자체 개발한 Rust BlueOS 커널을 추가했습니다.
  • 2025년, BlueOS 커널이 공식적으로 오픈 소스화되었고, Open Atom Open Source Foundation의 BlueKernel 인큐베이션 프로젝트가 되어 더욱 개방적인 공동 구축 단계에 진입했습니다.

BlueOS 발표 이후, BlueOS의 기술 로드맵도 지속적으로 발전해 왔습니다. 커널, 시스템 프레임워크부터 단말 AI에 이르기까지 지난 몇 년간의 축적이 오늘날 AgentOS 탐색의 기반을 형성했습니다. 이 4년간의 기반 덕분에 BlueOS는 "경계를 넘는" 데 성공했습니다.

과거 BlueOS의 적용 범위는 주로 스마트워치와 같은 IoT 장치에 집중되었습니다. 이번 AgentOS 기술 프리뷰는 BlueOS가 더 복잡한 단말 시나리오로 확장될 가능성을 보여주었습니다. 휴대폰에서의 작업 실행, 단말 코딩, 또는 휴대폰, 시계, PC 및 클라우드 간의 능력 스케줄링 등 모두 BlueOS가 기존 시스템 능력을 더 많은 장치와 사용 시나리오로 확장하려 시도하고 있음을 보여줍니다.

총평

vivo는 하위 기술력을 과시하며 업계의 질문에 답하고자 합니다. AI가 "대화"에서 "작업 수행"으로 진화할 때, 미래의 운영체제는 어떤 모습이어야 할까요? BlueOS AgentOS의 답은 "사용자와 디지털 세계를 연결하는 '슈퍼 작업 허브'가 되는 것"입니다.

이는 인간-기계 상호작용의 논리를 재정의할 것입니다. 사용자에게는 "앱 찾기, 버튼 클릭"에서 "목표 지시, 시스템 결과 제출"로 작업 방식이 변화하고, 개발자에게는 자신의 서비스가 Agent에 의해 즉시 이해되고 호출되도록 하는 것이 AI 시대의 새로운 입구를 선점하는 핵심이 될 것입니다.

BlueOS AgentOS의 이번 등장은 AGI 시대를 향한 첨단 기술의 예고편에 가깝지만, 이 강력한 시연을 통해 vivo는 차세대 운영체제의 진화 방향을 미래에 명확하게 제시했습니다.
